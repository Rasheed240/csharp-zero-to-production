===== Exercise 1: which locals become fields? =====

  Predict, then read. Three locals, one await, three different fates.

    hoisted : Task gate
    hoisted : Int32 <across>5__2

    'before' is used only before the await   -> NOT hoisted (a real local)
    'across' is used on both sides           -> hoisted
    'after'  is assigned after the await     -> NOT hoisted
  The rule is liveness, not declaration order: a local is hoisted only
  if its value must survive a suspension. This is why moving one line
  can change a method's memory profile without changing what it does.

===== Exercise 3: which of these allocate? =====

  variant                                bytes/call
    async Task<int>, returns 4242              72
    async Task<int>, returns 1                  0
    async Task (no result)                      0
    async ValueTask<int>, returns 4242          0
    async Task<int>, suspends                  96

  'async Task' with no result allocates nothing on the synchronous path:
  there is a shared already-completed Task singleton to hand back. Only
  Task<T> for an uncached T has to build one.

===== Exercise 4: where does the exception surface? =====

  (a) throw BEFORE the first await, method returns Task
      the call itself returned normally : task status Faulted
      it surfaced at the await : thrown before any await
      An async method NEVER throws at the call site, even for an
      argument check. The exception is captured into the Task.
      This is why argument validation belongs in a non-async wrapper:

  (b) the same check in a non-async wrapper
      threw at the CALL SITE, before any Task existed

  (c) throw AFTER an await
      surfaced at the await : thrown after an await

===== Exercise 5: count the suspensions =====

  Same method, same five awaits, different cache temperature.

  warm entries   suspensions   bytes/run   ms/run
             5             0           0        0
             3             2         760       34
             0             5        1624       80

  The source code did not change between those three rows. The number
  of awaits did not change. What changed is how many of them had to
  wait, and that is the only thing the cost depends on.
  This is the single most useful idea in the module: async is cheap
  when it does not suspend, and you control how often it suspends.
